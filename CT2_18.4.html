4 PART 3 — Parity, Checksum, Correction & Retransmission

Concept Comparison
Method What It Uses Purpose Automatically Corrects?
Even Parity Count of 1-bits Detect some changes No
Simple Checksum Sum of data values Detect some changes No
Error-Correcting Method Extra structured information Detect + may correct Sometimes
Retransmission Send the data again after a detected error Replace suspect copy Uses a new copy

Explain the Difference

Both are error-detection methods that append extra metadata alongside transmitted data to check if data was corrupted without altering original payload data.
Parity checks bit counts (even/odd 1s) for single bytes, whereas a simple checksum sums integer values across multi-number blocks.
Simple checksums can only flag errors—they cannot repair corrupt data automatically. Retransmission fetches an uncorrupted replacement copy.

Limitation Example

Original data: 4, 6  → Checksum = 10
Changed data:  5, 5  → Checksum = 10

It demonstrates a checksum collision: entirely different data sets can produce the exact same simple sum, causing corruption to slip through undetected.
